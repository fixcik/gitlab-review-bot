# Миграции PostgreSQL

- Старый код работает одновременно с новой схемой: удалять и переименовывать
  колонки можно только после того, как задеплоенный код перестал их использовать.
- Индексы на существующих таблицах — `CREATE INDEX CONCURRENTLY` (вне транзакции).
- Внешние ключи и CHECK — `NOT VALID`, затем `VALIDATE CONSTRAINT` отдельной миграцией.
- `NOT NULL` без `DEFAULT` на существующей таблице ломает вставки старого кода.
- Уже применённые миграции не правят — только новые.
