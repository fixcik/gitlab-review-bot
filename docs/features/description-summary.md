# Саммари в описании MR

Как у CodeRabbit («Summary by …»): бот держит в **описании** самого MR короткое
саммари изменений — на языке ревью (`review.default_language`, по умолчанию русский).
Заметка-саммари ревью (комментарий бота) остаётся как была.

```yaml
# config.yaml
review:
  description_summary: true   # по умолчанию false
```

Выключено по умолчанию: бот начинает писать в чужие описания. Репозиторий может
выключить у себя в `.reviewbot.yaml`: `description_summary: false` (включить вместо
сервиса нельзя, как и `diagram`).

## Как выглядит

```markdown
<!-- reviewbot:description-summary -->
**Саммари от ревью-бота**

Добавляет LRU-кэш заказов и исправляет пагинацию списка заказов.

**Новое**
- кэш заказов на 5 минут с вытеснением по LRU

**Исправления**
- последняя страница списка больше не теряется

**Тесты**
- тесты вытеснения и пагинации

<sub>Блок обновляется при каждом ревью; текст описания вне блока бот не меняет.</sub>
<!-- /reviewbot:description-summary -->
```

1–2 предложения о том, что делает MR, и список по группам — «Новое», «Исправления»,
«Рефакторинг», «Тесты», «Документация», «Прочее» (только непустые, до 8 пунктов,
каждый до 200 символов, весь блок до 6000 байт). Текст пишет модель в том же запуске
ревью (поле `description_summary` ответа), отдельного запуска нет. На
инкрементальном ревью модель обновляет саммари всего MR с учётом новых коммитов.

## Как бот пишет описание

- Перед записью бот заново читает MR и меняет только свой блок между маркерами:
  есть блок — заменяет его на месте, нет — добавляет в конец через пустую строку.
  Текст автора вне маркеров не меняется никогда.
- Не пишет, если описание не изменилось бы, MR — черновик, закрыт или смержен, модель
  не дала саммари или описание стало бы больше 1 МБ.
- **Отказ.** Автор добавил в описание `<!-- reviewbot:description-summary-off -->` — бот
  больше не трогает описание. Автор удалил блок — бот не добавляет его заново (заметка
  ревью помнит, что блок был записан). Сломанные маркеры (только начало или только
  конец) — бот ничего не делает.
- Если в тексте автора есть строка, которую GitLab может выполнить как quick action
  (`/close`, `/assign @x` в начале строки, вне блока кода), бот описание не переписывает:
  повторная отправка такого текста могла бы её выполнить.
- Обновляется при каждом ревью (новые коммиты), не при смене заголовка.

## Безопасность

Модель читает недоверенный код, поэтому её текст обезвреживается: одна строка на пункт,
символы Markdown и HTML экранированы (ссылок, картинок и HTML нет), упоминания `@`,
ссылки на задачи `#`, `!` и адреса `https://` разорваны, quick actions нейтрализованы,
HTML-комментарии (поддельные маркеры) обезврежены, пути песочницы ревью (`/work/`,
`/base/`, `/repos/`, `/skills/`) убираются из текста.

## Права

Менять чужое описание GitLab разрешает автору MR и ролям Developer и выше. Бот сначала
пишет своим токеном, при 403/404 — служебным (`GITLAB_SERVICE_TOKEN`). Если не вышло ни
так, ни так, ревью продолжается, а в «проблемы проверки» записывается
`description_summary_failed` («описание MR: нет прав»); токен, получивший отказ, час не
пробуется для этого проекта.
