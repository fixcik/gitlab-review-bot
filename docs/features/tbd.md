# Trunk-based development

Бот помогает держать привычки TBD: маленькие короткоживущие ветки, зелёный main и
изменения поведения, которые можно выключить без деплоя. Проверка обратной
совместимости — отдельно, в [compat.md](compat.md).

## Блок «🌿 Trunk-based» в саммари

```markdown
### 🌿 Trunk-based

- 📏 +520 / −80 строк, 14 файлов — ⚠️ больше 400: такой MR трудно ревьюить, лучше разбить на несколько
- 🕒 ветке 5 дней — ⚠️ дольше 3 дня: в TBD ветки живут часы, максимум пару дней
- ↩️ отстаёт от `main` на 45 коммитов — ⚠️ больше 30: обновите ветку (rebase), иначе проверялся не тот код, что попадёт в `main`
- ❌ пайплайн упал — main должен оставаться зелёным
```

| Строка | Откуда | Предупреждение |
|---|---|---|
| 📏 размер | все изменения MR (`/diffs`), без файлов из `ignore` и `review.default_ignore` (lock-файлы, `go.sum`, `vendor/`…); «≥», если GitLab свернул слишком большие диффы | `max_lines` |
| 🕒 возраст ветки | самая ранняя дата авторства коммитов MR (переживает rebase); без коммитов — дата создания MR | `max_age` |
| ↩️ отставание | `diverged_commits_count` GitLab: сколько коммитов целевой ветки нет в ветке MR | `max_behind` |
| пайплайн | head pipeline MR: ✅ прошёл, ❌ упал, ⏳ выполняется, ⏸ ждёт ручного запуска, ⚪ отменён / пропущен / нет; «для предыдущего коммита», если пайплайн не от последнего коммита | — |

Блок обновляется на каждом ревью. Пока пайплайн выполняется, бот каждые 2 минуты
перечитывает его статус и обновляет только эту строку саммари (без Claude, без
лимитов, не дольше 3 часов). Упавший пайплайн разбирается отдельно: блок «🔴 Пайплайн упал» с
упавшими job и тестами и объяснение причины ([ci.md](ci.md)). После перезапуска бота слежение возобновится со
следующим ревью.

`max_lines` — только предупреждение. Жёсткий порог — `review.max_mr_lines` (2000):
выше него Claude не запускается вовсе, а в саммари появляется блок «📦 MR слишком
большой для ревью» (см. [review.md](review.md#размер-mr)). Строки считаются одной
функцией, но жёсткий порог берёт проверяемый диапазон: на инкрементальном ревью —
только новые коммиты, тогда как блок TBD всегда показывает весь MR.

## Изменения поведения без возможности выключить

Если MR **меняет поведение того, чем уже пользуются**, а выключить новое поведение
без деплоя нельзя, бот пишет замечание уровня **major**: «Изменение поведения без
возможности выключить», с указанием, кого это затронет, и предложением, как спрятать
изменение за переключатель.

Флаг нужен, когда меняется:

- семантика или ответ существующего эндпоинта;
- обработка существующего события или сообщения;
- логика существующей джобы;
- что пишется в существующую таблицу или кэш;
- значение по умолчанию существующей настройки.

Флаг **не нужен** для того, чем ещё никто не пользуется: новый эндпоинт, новое
необязательное поле, новый тип события или потребитель, код, до которого
существующие вызовы не доходят, рефакторинг без изменения поведения, тесты,
документация. Обычный багфикс — только если он рискован для существующих вызовов.

Пока в команде нет системы флагов, засчитывается **любой** способ выключить без
деплоя: ключ конфига, переменная окружения, флаг, опция в запросе, если по умолчанию
остаётся старое поведение или переключение — это изменение конфига. Когда система
появится, опишите её в `review.tbd.flags_hint` (например
`flags.Enabled(ctx, "name") из pkg/flags`), и бот будет ждать именно её.

major не блокирует мерж при `review.block_min_severity: critical` (по умолчанию).

## Настройка

```yaml
# config.yaml
review:
  tbd:
    enabled: true
    max_lines: 400        # 0 — без предупреждения
    max_age: "72h"        # 0 — без предупреждения
    max_behind: 30        # 0 — без предупреждения
    pipeline: true        # строка пайплайна и её обновление
    feature_flags: true   # правило про выключаемость изменений поведения
    flags_hint: ""        # как у вас делаются флаги; пусто — любой переключатель
```

```yaml
# .reviewbot.yaml (из целевой ветки): пороги можно менять в обе стороны
tbd:
  enabled: true
  max_lines: 800
  max_age: "48h"
  max_behind: 50
  feature_flags: true
  flags_hint: ""
```
