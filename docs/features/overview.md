# Все возможности

Полный список того, что умеет бот. Короткий обзор — в [README](../../README.md).

- **Подключение по файлу**: бот ревьюит только репозитории с `.reviewbot.yaml` в целевой ветке MR (пустой файл — настройки по умолчанию; `review.require_repo_config: false` — все проекты групп). Файл проверяется строго: все ошибки сразу с номерами строк (опечатки в ключах с подсказкой, удалённые ключи с объяснением) — в одной заметке MR, на `/problems` и в `reviewbot validate-repo-config`; JSON Schema для подсказок в редакторе ([как подключить](../setup-gitlab.md#подключение-репозитория))
- **Саммари MR** с обзором файлов и Mermaid-схемой изменений, обновляется на каждом пуше
- **Inline-замечания** с severity и блоками `suggestion`; серьёзные блокируют мерж через тред
- **Инкрементальное ревью** новых коммитов; исправленные треды бот закрывает сам
- **Перепроверка перед публикацией**: critical и major замечания проходят отдельный запуск, который пытается их опровергнуть по коду; ложные отклоняются, преувеличенные понижаются, итог и причины — в саммари ([verify.md](verify.md))
- **Обратная совместимость** API, событий, миграций и конфига (oasdiff, buf, graphql-inspector + Claude) и свёрнутая **сводка изменений API** по эндпоинтам (OpenAPI 3.x и Swagger 2.0)
- **Покрытие нового кода** из артефакта CI (Cobertura, Clover, Go, LCOV); непокрытые изменённые строки бот отдаёт модели готовыми
- **Модель только читает**: у Claude лишь `Read`, `Grep`, `Glob` и только в каталогах запуска (клон, код до MR в `/base`, `/repos`, `/skills`; `/proc`, `/etc`, `$HOME` и прочее запрещены), никаких команд, Bash и setup; бот не запускает код репозитория, в песочнице нет языковых рантаймов ([security.md](../security.md))
- **Trunk-based**: размер MR, возраст ветки, отставание от main, статус пайплайна; изменения поведения без возможности выключить
- **Порог размера MR**: больше 2000 изменённых строк (`review.max_mr_lines`) — Claude не запускается, в саммари «📦 MR слишком большой» с советами, как разбить; секреты и детерминированная совместимость проверяются всё равно; ревью всё же — `review force` или метка `big-mr-ok` ([review.md](review.md#размер-mr))
- **Безопасность миграций БД** (SQL, Flyway, goose, golang-migrate, sqitch, Doctrine, Laravel, Alembic, Django): анализатор подсказывает Claude, где смотреть (блокировки, NOT NULL, смена типа, массовые изменения данных, правка старых миграций, удаление и переименование с кандидатами в задеплоенном коде), Claude проверяет и решает сам; мерж блокирует только поломка задеплоенного кода, подтверждённая строкой, которую бот перепроверяет
- **Разбор упавших пайплайнов**: упал пайплайн MR — в саммари упавшие job, упавшие тесты из отчёта JUnit и конец лога (без цветов, секретов и мусора раннера), а один запуск Claude объясняет в треде, почему упало (изменения MR со ссылками `файл:строка`, инфраструктура или флак) и как починить; тред закрывается, когда пайплайн проходит. Упал main — заметка в MR, после мержа которого он сломался, с упоминанием автора и того, кто смержил ([ci.md](ci.md))
- **Секреты и линтеры** на изменённых строках: gitleaks (все коммиты MR, всегда блокирует) и результаты линтеров из CI команды — отчёты GitLab Code Quality, SARIF или Checkstyle из пайплайна MR (phpstan, phpcs, ruff, eslint, golangci-lint, semgrep, архитектурные); сам бот линтеры не запускает ([lint.md](lint.md))
- **TODO без задачи**: добавленные `TODO`/`FIXME` в комментариях должны ссылаться на задачу (`TODO(PROJ-123): …`, `#12`, URL), иначе бот просит её завести; по желанию ключи проверяются в Jira ([подробнее](lint.md#todo-без-задачи))
- **Jira**: сверка MR с задачей и подсказка формата заголовка `feat: описание (PROJ-123)`
- **Контекст из других репозиториев** групп: кто использует меняемые API, таблицы, события
- **Карта системы**: кто какие эндпоинты, вебхуки, WebSocket/SSE предоставляет и вызывает (OpenAPI + лёгкая модель, инкрементально); в саммари — потребители затронутых контрактов, на `/map` — граф и неразрешённые вызовы; для MR — зависимости от ещё не задеплоенного в соседних репозиториях и связанные открытые MR с порядком мержа (только подсказка в саммари, ничего не блокирует)
- **MCP-инструменты в ревью** (выключено по умолчанию): модель берёт данные по запросу (строки диффа, линтеры, изменения API, карта системы, миграции, покрытие, задача) и отправляет каждое замечание через `submit_finding` — бот сразу проверяет его теми же правилами, что при публикации, и отвечает, что исправить; публикация по-прежнему в конце одной пачкой ([mcp.md](mcp.md))
- **Обучение** на ответах и действиях команды, **память проекта** о сборке и тестах
- **Скиллы команды** (`SKILL.md`) из папки на сервере: Claude сам открывает подходящие
- **Вопросы боту** в любом треде, лимиты на пользователя и общий лимит запусков
- **Реакции**: 👀 команда принята, ✅ / ❌ / ⏳ / 🚫 чем закончилась, ❤️ / 👍 на «спасибо» и «ок» без запуска Claude, 🧠 запомнено правило, 🎉 ревью без замечаний ([reactions.md](reactions.md))
- **Модели**: ревьюит Sonnet, в сложных случаях советуется с Opus, широкий поиск отдаёт Haiku
- **Автоматические метки MR** по путям, фактам бота (миграции, API, размер, секреты, тесты) и условиям словами, которые решает модель; бот снимает только свои метки ([подробнее](labels.md))
- **Проблемы проверки**: бот сам сообщает, что не смог проверить (линтер не запустился, нет отчёта о покрытии, нет доступа к связанному репозиторию, дифф обрезан, модель не смогла что-то проверить) — блок «⚠️ Не удалось проверить» в саммари, упоминание ответственных при новой проблеме, страница `/problems` с подсказками ([problems.md](problems.md))
- **Наблюдаемость**: `/usage` (расход токенов), `/runs` (диагностика за 48 часов), `/map` (карта системы), `/problems` (что бот не смог проверить), `/knowledge` (выученные правила, память о проектах, точность замечаний), `/` (главная: состояние за сутки, что требует внимания, разделы), `/metrics` (Prometheus) и `/readyz`; готовые дашборд Grafana, алерты и scrape config — в `deploy/grafana`, `deploy/prometheus` ([metrics.md](../metrics.md#дашборд-и-алерты)); трейсы OpenTelemetry (выключено по умолчанию): трасса на каждое ревью со спанами GitLab, анализаторов, запусков Claude (модель, токены, стоимость) и публикации в Tempo, Collector или Grafana Cloud, `trace_id` в логах и на `/runs` — без кода, промптов и токенов ([tracing.md](tracing.md))
