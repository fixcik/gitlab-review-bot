# Команды

Бот откликается на упоминание своего аккаунта — `@<username>` того пользователя, чей
токен в `GITLAB_TOKEN`. Отдельной настройки имени нет (`review.bot_mention` устарел и
игнорируется). Ниже бот называется `@reviewbot`; `@reviewbot help` покажет команды уже
с правильным именем.

## Как бот разбирает сообщение

- Упоминание ищется как отдельное слово, без учёта регистра (`@reviewbot.` в конце
  предложения подходит, `@reviewbot2` и `@reviewbot.foo` — нет).
- Команда — текст **после** упоминания; разделители `, : ; — -` сразу после
  упоминания пропускаются. Если упоминание в конце, текст до него — вопрос.
- Команда должна занимать всё сообщение (одну строку). Регистр, лишние пробелы и
  `.`, `!`, `?` в конце не важны. Всё остальное — вопрос боту.
- Голое упоминание без текста — `help`.
- Сообщение, которое целиком — благодарность или подтверждение («спасибо!», «ок,
  поправлю», 🙏, 👍), — не вопрос: бот отвечает реакцией ([reactions.md](reactions.md)).
- Заметки самого бота и системные заметки игнорируются.
- **Тред команды.** В GitLab 19.x обычный комментарий к MR — резолвимый тред, и
  незакрытый он блокирует мерж при «All threads must be resolved». Поэтому после
  ответа на служебную команду (`review`, `full review`, `review force`, `help`,
  `pause`, `resume`, `ignore`, `resolve`, `config`, `check`) бот закрывает тред,
  который начала сама команда, служебным токеном (`GITLAB_SERVICE_TOKEN`; без него
  тред остаётся открытым — закройте вручную: чужой тред бот своим токеном закрыть не может). Не закрываются: вопросы, правила и
  память (на ответ можно ответить в том же треде) и треды замечаний бота, даже если
  команду написали ответом внутри такого треда.

## Ревью

| Команда | Действие |
|---|---|
| `@reviewbot review` | ревью коммитов после последнего проверенного; если новых нет — ответ «Новых коммитов с последнего ревью…» без расхода лимитов |
| `@reviewbot full review` | полное ревью MR заново |
| `@reviewbot review force` | полное ревью, даже если MR больше `review.max_mr_lines` (иначе вместо ревью — «📦 MR слишком большой для ревью»; см. [review.md](review.md#размер-mr)) |
| `@reviewbot check` | перепроверить **открытые** замечания бота на текущем коде без нового коммита и закрыть исправленные |

После ревью бот отвечает: «✅ Ревью выполнено (`1a2b3c4d..5e6f7a8b`): новых замечаний —
3, закрыто — 1. Сводка обновлена.» Для Draft, закрытого MR, выключенного бота или
сломанного `.reviewbot.yaml` бот отвечает, почему ревью не будет. В репозитории без
`.reviewbot.yaml` в целевой ветке (не подключён, `review.require_repo_config`) любая
команда, кроме `help`, получает один ответ, как подключить репозиторий
([review.md](review.md#какие-репозитории-ревьюятся)). Ручное ревью
работает и на паузе, и при `ignore` в описании. Подробнее — [review.md](review.md).

### Перепроверка открытых замечаний

`@reviewbot check` (`recheck`, `проверь`, `перепроверь`) — когда замечание исправили
не коммитом в этот MR (правка в другом MR, вынесли в общий код, разобрались в треде)
или ревью не запускалось, а треды бота висят открытыми.

- **В общем обсуждении MR** (или в любом треде, который не является замечанием бота) —
  все открытые замечания бота. **В треде замечания** — только оно.
- Нет открытых замечаний — ответ «Открытых замечаний бота нет.» без запуска Claude и
  без расхода лимитов.
- Иначе один короткий запуск Claude на текущем head (модель `claude.model`, без
  советника и субагента поиска, только чтение файлов и поиск, плюс контекст других
  репозиториев): по каждому замечанию — «исправлено» (с одной фразой со ссылкой на
  код) или «не исправлено». Новых замечаний он не ищет; если не уверен — замечание
  остаётся открытым.
- Исправленные закрываются так же, как при ревью ([review.md](review.md#автозакрытие-исправленного)):
  ответ в треде и закрытие служебным токеном; без него — «✅ Похоже, исправлено…
  _Тред можно закрыть._». Строка «Мерж заблокирован» в саммари пересчитывается.
- Ответ в треде команды: «Проверил 3 открытых замечания на `5e6f7a8b`: закрыто 1,
  остаются 2.» и список оставшихся (до 10, остальные под спойлером).
- Треды линтеров и несовместимых изменений команда **не** перепроверяет (для них
  нужен запуск линтеров и oasdiff) — ответ говорит, сколько их открыто: они закроются
  после следующего пуша или ревью. Команда в таком треде отвечает так же, без запуска.
- Лимиты: считается перезапуском (`limits.user_reruns_per_hour`) и входит в общий
  лимит, но cooldown MR (`limits.mr_rerun_cooldown`) к ней не применяется и после неё
  не начинается. При лимите использования Claude — «⏳ Перепроверка отложена до
  15:40: …», повтор автоматически.

## Вопросы

`@reviewbot почему здесь mutex, а не канал?` — ответ в том же треде. В треде замечания
бот учитывает обсуждение и может закрыть тред, если вопрос исчерпан. Вопрос с
обоснованным несогласием в треде бота может стать правилом команды
([learning.md](learning.md)).

Чистое «спасибо» (`@reviewbot спасибо!`) или «ок» в треде замечания бота
(`@reviewbot ок, поправлю`) — не вопрос: бот ставит ❤️ / 👍 без запуска Claude и без
ответа. `@reviewbot исправил` остаётся вопросом: бот проверит код и может закрыть
тред. Реакции на команды (👀 → ✅ / ❌ / ⏳ / 🚫) — [reactions.md](reactions.md).

## Управление MR

| Команда | Действие |
|---|---|
| `@reviewbot pause` | остановить **автоматическое** ревью этого MR. Ответ «⏸ Авторевью на паузе. Продолжить: `@reviewbot resume`», в саммари строка «⏸ Авторевью на паузе (поставил @alice)». Разбор упавших пайплайнов этого MR ([ci.md](ci.md)) тоже на паузе. Ручное ревью, вопросы и правила работают. После команды можно дописать причину: `@reviewbot пауза — идёт рефакторинг` |
| `@reviewbot resume` | снять паузу: «▶️ Авторевью возобновлено.» Если за время паузы пришли непроверенные коммиты, ревью ставится в очередь: «… Есть непроверенные коммиты — ревью поставлено в очередь.» |
| `@reviewbot ignore` | работает только **в описании MR**: пока строка есть в описании, авторевью не запускается. В комментарии бот лишь объясняет, как пользоваться |
| `@reviewbot resolve` | закрыть все открытые треды бота в MR (замечания, несовместимые изменения, линтеры), включая блокирующие; саммари получает «✅ Блокирующих замечаний нет.». Нужен служебный токен, иначе «У бота нет прав закрывать треды…» |
| `@reviewbot config` | таблица действующих настроек для MR и их источник: «сервис», «`.reviewbot.yaml`» или «по умолчанию». Без токенов, секретов и URL |

Пауза хранится в базе бота по MR и переживает перезапуск. Закрытые командой
`resolve` треды совместимости и блокирующих линтеров считаются принятыми и больше не
блокируют (см. [compat.md](compat.md#ручное-закрытие)).

Что показывает `config`: `enabled`, `language`, `auto_review`, пауза, маркер `ignore`,
пользовательские и общий лимиты, `block_min_severity`, совместимость (и доп. пути и
команды), контекст (и `context.exclude`), обучение, инструменты модели (всегда
только чтение), `ignore`,
`max_files`, наличие `instructions`, Jira и ключи, проверка заголовка, схема,
[метки MR](labels.md) (вкл/выкл и имена меток из правил).

## Правила команды

| Команда | Действие |
|---|---|
| `@reviewbot запомни <правило>` | запомнить правило; область выберет модель |
| `@reviewbot запомни для всех: <правило>` | для всех репозиториев |
| `@reviewbot запомни <правило> (только здесь)` | только для этого репозитория |
| `@reviewbot правила` | список и статистика |
| `@reviewbot забудь #12` | удалить |
| `@reviewbot правило #12 для всех` | сделать общим |
| `@reviewbot правило #12 только здесь` | ограничить репозиторием |

Слова области: «для всех» — `для всех`, `для всех репозиториев`, `для всех
проектов`, `везде`, `глобально`, `global`, `globally`, `for all`, `everywhere`;
«только здесь» — `только здесь`, `только для этого проекта`, `только для
репозитория`, `здесь`, `локально`, `для проекта`, `local`, `locally`, `here`, `only
here`, `this project only`, `this repo only`, `project`. Подсказку области можно
поставить в начало (`запомни для всех: …`), в конец через запятую, тире или в скобках.
`запомни` может занимать несколько строк. Подробнее — [learning.md](learning.md).

## Память проекта

| Команда | Синонимы |
|---|---|
| `@reviewbot память` | `memory`, `память проекта`, `память показать`, `память покажи`, `memory project`, `memory show`, `memory list` |
| `@reviewbot память очистить [раздел]` | глаголы `очистить`, `очисти`, `сбросить`, `сбрось`, `clear`, `reset`, `wipe`; «всё» — без раздела или `всё`, `все`, `всю`, `целиком`, `полностью`, `all`, `everything` |
| `@reviewbot память запомни <раздел>: <текст>` | глаголы `запомни`, `запомнить`, `добавь`, `добавить`, `add`, `remember` |

Подробнее — [memory.md](memory.md).

## Help

`@reviewbot help` (или просто `@reviewbot`) — список команд с правильным именем бота и
остаток лимитов на ближайший час:

```markdown
**Оставшиеся лимиты на ближайший час:**
- перезапуски ревью: 4
- вопросы: 19
- общий лимит запусков: 11
- перезапуск одного MR — не чаще раза в 10 мин
```

Команды правил и памяти в справке показываются, только если эти функции включены в
сервисе.
