# Память проекта

У каждого репозитория своя **операционная память**: то, на выяснение чего у Claude
ушло больше двух шагов, — где что лежит, как устроены модули, как проект
собирается и тестируется (по его же `Makefile` и CI), какой код генерируется и где
подводные камни. Без неё бот выяснял бы это заново в каждом запуске. Команд Claude
не запускает, поэтому всё это — знание из файлов репозитория, а не проверенные
запуски.

Память читается в начале каждого ревью, ответа на вопрос и перепроверки
(замечаний и совместимости) и обновляется в конце ревью и ответа (перепроверка только читает).

## Что хранится

| Раздел | Пример пункта |
|---|---|
| Сборка (`build`) | `make build` — нужен сгенерированный код (`make gen`) |
| Тесты (`test`) | Юнит-тесты: `make test-unit`; `go test ./...` падает в `internal/store` — нужен docker |
| Линт (`lint`) | `golangci-lint run ./...` с `.golangci.yml`, `--timeout 5m` |
| Подготовка окружения (`setup`) | перед тестами нужен `make deps` (кодоген protobuf) |
| Структура проекта (`structure`) | хендлеры в `internal/http`, миграции в `db/migrations` |
| Подводные камни и неудачные попытки (`pitfalls`) | `npm test` без `CI=true` зависает в watch-режиме |
| Прочее (`other`) | — |

- **Где.** Только в базе бота (таблица `project_memory`), никогда в репозитории.
  Привязана к числовому ID проекта: переименованный или перенесённый репозиторий её не
  теряет; между проектами не разделяется.
- **Что записывается.** Claude возвращает необязательное поле `memory_updates`
  (`add` / `replace` / `remove` по разделам): где лежат обработчики, миграции,
  контракты и тесты, карту модулей, как проект собирается и тестируется по его
  `Makefile` и CI, шаги кодогенерации и сгенерированные файлы, подводные камни,
  исправления неверных фактов. Детали
  конкретного MR, мнения о коде (это [правила команды](learning.md)), секреты и
  персональные данные не записываются.
- **Слияние.** Пункты чистятся от секретов, почти одинаковые схлопываются (совпадение
  ≥ 85% слов). На раздел — до `min(1500, review.memory.max_chars)` символов, на проект —
  `review.memory.max_chars` (6000). Разросшийся раздел после ревью или ответа сжимает
  `claude.light_model` (без инструментов; учитывается в общем лимите и в лимите обучения
  `review.learn.max_per_hour`, на `/usage` — как «Память проекта»). Если сжать не
  удалось или один из лимитов исчерпан, остаются самые свежие
  пункты.

## Как выглядит в MR

В саммари:

```markdown
<details><summary>📒 Память проекта: обновлено 2 пункта (Тесты, Линт)</summary>

- **Тесты** · добавлено: Юнит-тесты: `make test-unit`
- **Линт** · исправлено: `golangci-lint run ./...` с `--timeout 5m`

Память видна только боту (хранится в его базе, не в репозитории). Показать: `@reviewbot память` · очистить раздел: `@reviewbot память очистить <раздел>`
</details>
```

В ответе на вопрос — приписка «📒 Обновил память проекта: 1 пункт (Тесты). Показать:
`@reviewbot память`.»

## Память ничего не разрешает

Память — текст для промпта, а не настройки. Она не меняет того, что может модель
(только `Read`, `Grep`, `Glob`; команд нет вовсе), даже если в ней записана
команда: prompt injection через память не даёт ничего запустить. Подсказок
«добавьте в `tools` / `setup`» больше нет — этих ключей нет
([configuration.md](../configuration.md#удалённые-ключи)).

## Команды

Developer и выше, без запуска Claude и без лимитов.

| Команда | Действие |
|---|---|
| `@reviewbot память` (`memory`) | показать память: разделы, когда и в каком MR обновлены |
| `@reviewbot память очистить` (`memory clear`) | очистить всю память проекта |
| `@reviewbot память очистить тесты` (`memory clear test`) | очистить один раздел |
| `@reviewbot память запомни линт: <текст>` (`memory add lint: <text>`) | добавить пункт вручную |

Разделы в командах: `сборка`, `тесты`, `линт`, `подготовка окружения`, `структура
проекта`, `подводные камни`, `прочее` или `build`, `test`, `lint`, `setup`,
`structure`, `pitfalls`, `other` (и синонимы, например `окружение`, `грабли`,
`gotchas`). Синонимы команд — в [commands.md](commands.md#память-проекта).

## Настройка

```yaml
# config.yaml
review:
  memory:
    enabled: true
    max_chars: 6000
```

```yaml
# .reviewbot.yaml — не читать и не писать память этого репозитория
memory:
  enabled: false
```

## Ограничения

- Память может устареть: если запомненный факт не подтвердился в коде, Claude
  сообщает об этом через `memory_updates`, и пункт исправляется.
- Сбросить память можно только командами в MR (или напрямую в базе).
