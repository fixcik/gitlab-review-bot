# Jira и заголовок MR

Две связанные функции:

1. **Соответствие задаче** — бот находит задачи Jira, связанные с MR, и Claude
   сверяет изменения с ними. Нужна Jira Data Center / Server (REST API v2, Personal
   Access Token).
2. **Подсказка про заголовок** — проверка формата заголовка MR. Работает и без Jira.

Обе функции ничего не блокируют: результат только в саммари.

Ключи задач в комментариях `TODO`/`FIXME` проверяет отдельная проверка «TODO без
задачи» ([lint.md](lint.md#todo-без-задачи)); с `review.todo.verify_keys: true` она
тоже читает Jira (существует ли ключ).

## Формат заголовка

Conventional Commits с ключом задачи в скобках в конце:

```
feat: описание (PROJ-123)
fix(auth)!: вход по SSO (PROJ-45)
```

- Типы — `jira.title_types` (по умолчанию `feat`, `fix`, `refactor`, `perf`, `chore`,
  `docs`, `test`, `build`, `ci`, `style`, `revert`); область `(scope)` и `!`
  необязательны.
- Префиксы черновика `Draft:`, `[Draft]`, `(Draft)`, `WIP:` при проверке
  отбрасываются.
- `jira.require_key_in_title: false` — не требовать ключ в заголовке.

Если заголовок не в этом формате, модель предлагает свой (`suggested_title`), а бот
добавляет ключ задачи. Предложенный заголовок — **на английском** (`jira.title_language`,
по умолчанию `en`, независимо от `review.default_language`) и следует встроенному
формату: Conventional Commits, scope — модуль или подсистема (не имя файла), описание
в повелительном наклонении и настоящем времени со строчной буквы, без точки в конце,
весь заголовок — до 72 символов, суть изменения, а не список файлов, без ключа Jira и
эмодзи. Формат можно заменить своим текстом — в сервисе или для репозитория
(репозиторий важнее):

```yaml
# config.yaml
jira:
  title_language: en
  title_prompt: |
    Use Conventional Commits: `type(scope): description`, type is one of: {types}.
    Scope is the service area (api, billing, ui). Description in {language},
    imperative, lowercase, no trailing period, at most 60 characters.
```

```yaml
# .reviewbot.yaml
jira:
  title_language: ru
  title_prompt: "Conventional Commits, тип из {types}; описание на языке {language}, до 72 символов."
```

`{types}` и `{language}` подставляются как текст (это не шаблон, другие `{слово}` —
ошибка конфига); текст — до 4000 байт. Как и `instructions`, это указания
сопровождающих проекта модели, они попадают в промпт ревью.

## Как бот находит задачу

Ключи вида `PROJ-123` ищутся в заголовке, названии ветки, описании MR и сообщениях
коммитов (до 200 коммитов) — в таком порядке приоритета. Принимаются только
префиксы из `jira.project_keys` (пусто — любые). `_` считается разделителем:
`feature_PROJ-1` и `PROJ-123_fix` распознаются. Берутся не больше **трёх** задач.

Ключи проекта задаются в сервисе и могут быть заменены для репозитория:

```yaml
# config.yaml
jira:
  project_keys: ["PROJ"]
```

```yaml
# .reviewbot.yaml
jira:
  project_keys: ["PAY"]   # в этом репозитории задачи ищутся только в PAY
```

Тот же ключ используется в подсказке: `feat: описание (PAY-?)`.

## Как выглядит в MR

### Подсказка про заголовок

В начале саммари:

```markdown
> 💡 **Заголовок MR.** Ключ задачи **PROJ-45** найден в названии ветки, но не в заголовке. Добавьте его в конец заголовка в скобках.
>
> Предлагаемый заголовок: `feat(auth): вход по SSO (PROJ-45)`
```

Варианты сообщений:

| Ситуация | Сообщение |
|---|---|
| ключ в заголовке, но не в конце в скобках | «Ключ задачи **PROJ-45** нужно указать в конце заголовка в скобках.» |
| ключ в ветке, описании или коммитах | «Ключ задачи **PROJ-45** найден в названии ветки, но не в заголовке…» (задача всё равно проверяется) |
| ключа нет нигде | «В MR не найден ключ задачи Jira (ни в заголовке, ни в ветке, описании или коммитах)…»; в предложении `(PROJ-?)` |
| заголовок не в формате | «Заголовок не соответствует формату Conventional Commits `тип(область): описание (PROJ-123)`. Допустимые типы: …» |

Если заголовок не в формате, Claude предлагает тип, область и описание; бот
подставляет ключ сам.

**Смена заголовка.** Если в MR изменился только заголовок (без новых коммитов), бот
обновляет подсказку в существующем саммари — без Claude, без ревью и без расхода
лимитов. Если саммари ещё нет, ничего не происходит.

### Соответствие задаче

Раздел саммари (только при включённой Jira и найденных ключах):

```markdown
### 📋 Соответствие задаче

**Задачи:**
- [PROJ-45](https://jira.example.com/browse/PROJ-45) — Вход по SSO (Story, In Progress)

**Вердикт:** 🟡 частично

**Реализовано:**
- редирект на IdP и обработка callback

**Не хватает:**
- выход из системы (logout) из критериев приёмки

**Сверх задачи:**
- переименование пакета auth
```

Вердикты: ✅ соответствует, 🟡 частично, 🔴 расходится, ❔ неясно.

Claude видит описание задачи, статус, тип, последние `jira.comments_limit`
комментариев, а для подзадач — родителя и эпик (`jira.epic_link_field`). Тексты из
Jira передаются как недоверенные данные.

Если задачу получить не удалось, бот пишет об этом и продолжает ревью:

| Ошибка Jira | Текст в саммари |
|---|---|
| 404 | «⚠️ не удалось получить из Jira: задача не найдена» |
| 401 / 403 | «⚠️ не удалось получить из Jira: нет доступа (проверьте токен Jira и права на проект)» |
| сеть, 5xx | «⚠️ не удалось получить из Jira: ошибка запроса к Jira» |

## Настройка

```yaml
jira:
  url: "https://jira.example.com"     # пусто — Jira выключена, подсказка работает
  # token: лучше env JIRA_TOKEN
  # ca_file: "/etc/ssl/internal-ca.pem"
  project_keys: ["PROJ"]
  epic_link_field: "customfield_10008"
  comments_limit: 10
  title_check: true
  require_key_in_title: true
  title_types: [feat, fix, refactor, perf, chore, docs, test, build, ci, style, revert]
  title_language: en                 # язык предлагаемого заголовка
  title_prompt: ""                   # свой формат заголовка; пусто — встроенный
```

Токен Jira остаётся в сервисе: в песочницу, промпты и логи он не попадает.
Отключить подсказку: `jira.title_check: false`.

## Ограничения

- Только Jira Data Center / Server (REST v2, `Authorization: Bearer <PAT>`); Jira Cloud
  не поддерживается.
- Только чтение: бот не меняет задачи и не пишет в них комментарии.
- Эпик берётся через поле Epic Link на один уровень.
- Подсказка в саммари — единственный механизм: заголовок MR бот не меняет.
