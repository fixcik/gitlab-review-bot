# Лимиты

Лимиты защищают подписку или бюджет API от перерасхода. Все окна — скользящий час:
запись старше часа выходит из окна. Запуск записывается, когда Claude **реально
стартует**, поэтому схлопнутые, пропущенные и отклонённые задачи ничего не стоят.

## Какие лимиты есть

| Лимит | Ключ | По умолчанию | Что считает |
|---|---|---|---|
| общий | `limits.global_runs_per_hour` | 15 | все запуски Claude: ревью, вопросы, перепроверки (замечаний и совместимости), обучение, синтез правил, сжатие памяти |
| перезапуски | `limits.user_reruns_per_hour` | 5 | запуски по `review` / `full review` / `review force` / `check` пользователя |
| cooldown MR | `limits.mr_rerun_cooldown` | 10m | интервал между ручными перезапусками одного MR (любыми пользователями); `check` его не проверяет и не начинает |
| вопросы | `limits.user_chat_per_hour` | 20 | запуски по вопросам пользователя |
| обучение | `review.learn.max_per_hour` | 30 | извлечение правил из ответов, `запомни`, синтез правил; сжатие памяти (входит в этот счётчик и останавливается им, как и общим лимитом) |
| параллельность | `limits.max_concurrent` | 2 | одновременно обрабатываемые задачи (у одного MR — всегда одна) |

- `0` в лимите — без ограничения.
- `limits.exempt_users` — логины без пользовательских лимитов; общий лимит действует
  и на них.
- `.reviewbot.yaml` может только ужесточить пользовательские лимиты
  (`limits.user_reruns_per_hour`, `limits.user_chat_per_hour`,
  `limits.mr_rerun_cooldown`): меньший лимит или больший cooldown. Если в сервисе
  лимит выключен (`0`), положительное значение из репозитория действует. Общий лимит
  задаётся только в сервисе.
- В общем лимите каждый запуск считается отдельно, включая повтор при неверном ответе
  Claude (бот повторяет один раз с подсказкой), перепроверку замечаний и совместимости и
  повтор без MCP. Пользователю команда засчитывается один раз: эти дополнительные запуски
  той же команды не расходуют `user_reruns_per_hour` / `user_chat_per_hour` и не
  перезапускают cooldown MR.
- Автоматическое ревью пользовательских лимитов не расходует, только общий.
- Слишком большой MR (`review.max_mr_lines`, см. [ревью](review.md#размер-mr)) Claude не
  запускает, поэтому размер проверяется до лимитов: такой MR получает блок «📦 MR
  слишком большой» и ответ на `review`, даже когда лимиты исчерпаны, и лимиты не тратит.

Остаток лимитов показывает `@reviewbot help`.

## Что происходит при исчерпании

| Что | Общий лимит | Пользовательский лимит | Лимит использования Claude (подписка/API) |
|---|---|---|---|
| авторевью | откладывается до освобождения окна; в саммари «⏳ Ревью отложено до 15:40: Глобальный лимит ревью исчерпан (15 в час)…» | — | откладывается до времени сброса (или на 30 мин, если Claude его не сообщил); «⏳ Ревью отложено до 15:40: достигнут лимит использования Claude» |
| `review` / `full review` | ответ «⛔ Глобальный лимит ревью исчерпан…», не повторяется | ответ «⛔ Лимит перезапусков исчерпан (5 в час). Следующий будет доступен в 15:12.» или «⛔ Перезапуск этого MR возможен не чаще раза в 10 мин. Следующий — в 15:05.» | ответ «⏳ Ревью отложено до 15:40: достигнут лимит использования Claude»; повтор автоматически, без повторной проверки лимитов пользователя |
| `check` | ответ «⛔ Глобальный лимит ревью исчерпан…» | ответ «⛔ Лимит перезапусков исчерпан…» (cooldown MR не действует) | ответ «⏳ Перепроверка отложена до 15:40: достигнут лимит использования Claude»; повтор автоматически |
| вопрос | ответ «⛔ Глобальный лимит ревью исчерпан…» | ответ «⛔ Лимит вопросов исчерпан (20 в час)…» | ответ «⏳ Достигнут лимит использования Claude, отвечу после 15:40.»; повтор автоматически |
| обучение из ответа, синтез | пропускается (запись в логе) | — | пропускается |
| `запомни` | правило сохраняется как написано: «_Сформулировано без Claude (…), сохранено как написано._» | — | то же |
| перепроверка ([verify.md](verify.md)) | замечания публикуются как есть с пометкой в саммари; пункты совместимости — «не перепроверено» и блокируют; проблема `verify_failed` | — | то же |
| сжатие памяти | остаются самые свежие пункты | — | то же |

### Отложенные задачи

- Отложенная задача ждёт в очереди бота до указанного времени и запускается снова.
  Время — момент сброса лимита из ответа Claude (без него — через 30 минут), но не
  дальше суток: при более позднем сбросе задача пробует снова через сутки. Число
  повторов не ограничено: задача повторяется, пока не выполнится или не будет
  заменена. Пока отложенная команда ждёт, следующие команды и вопросы в этом MR
  выполняются, не дожидаясь её.
- Новое авторевью того же MR (новый пуш) заменяет отложенное; признак «полное ревью»
  сохраняется.
- Вся очередь хранится в SQLite и переживает перезапуск бота: ожидающие и отложенные
  авторевью (по одному на MR, новое заменяет старое) ставятся в очередь снова на
  сохранённое время, ручные задачи (`review`, вопросы, команды) — в прежнем порядке.
  Команда, отложенная лимитом Claude или прерванная остановкой после того, как её
  запуск Claude уже учтён, после перезапуска не проверяется по пользовательским лимитам
  и паузе между перезапусками MR повторно и не учитывается пользователю второй раз
  (общий лимит действует как обычно). Ручные задачи старше `queue.manual_max_age`
  (по умолчанию 6 ч) после перезапуска отбрасываются. Подробно —
  [deploy.md](../deploy.md#перезапуск-без-потерь).
- Отложенные и повторные задачи видны в `/runs` со статусом `postponed` и временем
  повтора (см. [usage-and-diagnostics.md](../usage-and-diagnostics.md)).

## Виды запусков

Для лимитов бот хранит записи `usage` (24 часа):

| Вид | Что |
|---|---|
| `auto` | запуски авторевью (включая перепроверку) |
| `rerun` | запуски `review` / `full review` / `review force` и `check` (без MR: cooldown на неё не действует); перепроверка и другие дополнительные запуски той же команды — без пользователя и MR |
| `chat` | вопросы |
| `learn` | обучение, синтез правил, сжатие памяти |

Отдельно на `/usage` запуски делятся по типам «Ревью», «Вопросы (чат)», «Перепроверка»,
«Обучение», «Память проекта», «Прочее» (см.
[usage-and-diagnostics.md](../usage-and-diagnostics.md#на-кого-записывается-запуск)).

## Как подобрать значения

- Одно ревью — один запуск Claude, плюс один на перепроверку, если Claude нашёл
  critical/major замечания или несовместимые изменения (они перепроверяются одним
  запуском). Обучение и сжатие памяти — короткие запуски лёгкой
  модели.
- `global_runs_per_hour` ≈ пиковое число пушей в час × 1,5. При подписке Claude
  ограничивает и сам: такие запуски бот откладывает, а не теряет.
- `max_concurrent` упирается в CPU/память хоста: каждый запуск — контейнер с
  `sandbox.cpus` и `sandbox.memory`.
- Расход токенов смотрите на `/usage`; как снизить — в
  [troubleshooting.md](../troubleshooting.md#большой-расход-токенов).
