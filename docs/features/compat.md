# Обратная совместимость

Команды с trunk-based development выкатывают изменения rolling deploy: старая и
новая версии сервиса какое-то время работают одновременно. Изменение должно быть
совместимо **в обе стороны**. Бот находит несовместимые изменения и блокирует мерж,
пока их не исправят или осознанно не примут.

## Что считается несовместимым

- **API** (REST с OpenAPI и без, gRPC/proto, GraphQL): удалены или переименованы
  эндпоинты, методы, поля, значения enum; изменён тип; необязательное поле запроса
  стало обязательным; удалено поле ответа; ужесточена валидация; изменены коды
  ответа, формат ошибок, семантика или значения по умолчанию.
- **События и сообщения** (Kafka, очереди, вебхуки): payload, который не прочитают
  потребители предыдущей версии или который сломает продюсеров предыдущей версии.
- **Миграции БД** не по схеме expand/contract: DROP/RENAME колонки или таблицы,
  которую ещё использует предыдущая версия; NOT NULL без default на существующей
  таблице; сужение типа.
- **Конфигурация**: удалены или переименованы переменные окружения и настройки, от
  которых зависят предыдущая версия или деплойменты.

## Как проверяется

### 1. Инструменты (без LLM)

Бот находит спецификации, изменённые в MR (`merge base..head`):

| Тип | Как находится | Инструмент |
|---|---|---|
| OpenAPI 3.x и Swagger 2.0 | `**/openapi*.{yaml,yml,json}`, `**/swagger*.{yaml,yml,json}`, любой YAML/JSON с ключом верхнего уровня `openapi:`/`swagger:`, плюс `compat.openapi` | `oasdiff changelog --fail-on ERR` (Swagger 2.0 — после `oas2to3`, см. ниже) |
| proto | `**/*.proto` плюс `compat.proto` | `buf breaking` по модулю: каталог с `buf.yaml`/`buf.work.yaml`, иначе корень репозитория |
| GraphQL | `**/*.graphql`, `**/*.graphqls`, `**/schema.gql` плюс `compat.graphql` | `graphql-inspector diff` |

Версия из merge base и версия из MR кладутся рядом во временный каталог клона
(`git cat-file blob`, без textconv и фильтров). Инструменты работают в песочнице
`--network none`, без токенов, без shell, с таймаутом `review.compat_timeout`.
Новые спецификации не проверяются, удалённые передаются Claude как данные.

Ограничения инструментов:

- внешние `$ref` в OpenAPI по URL или абсолютному пути и зависимости buf из BSR не
  загружаются — такая проверка отмечается как невыполненная (подробнее —
  [внешние `$ref`](#внешние-ref));
- `.proto` вне модулей buf не проверяются buf («файл вне модулей buf (buf.yaml) — не
  проверен buf»), их смотрит Claude;
- предупреждения oasdiff уровня WARN не блокируют, они попадают в свёрнутый блок
  «Возможные несовместимости, которые инструменты не смогли подтвердить».

Своих проверок-команд (`compat.commands`) больше нет: они запускали программы
репозитория в клоне MR, то есть код, который MR может изменить, и требовали рантаймов
(Go, PHP, Python), которых в образе песочницы больше нет. `.reviewbot.yaml` с этим
ключом не разбирается (`compat.commands: removed: the bot no longer runs repository
commands …`, [configuration.md](../configuration.md#удалённые-ключи)). Такие проверки
переносите в CI (job, который падает на несовместимом изменении). Треды `custom`,
опубликованные до обновления, бот не закрывает сам — их закрывает человек.

#### Swagger 2.0

oasdiff понимает только OpenAPI 3.x: на файлах Swagger 2.0 он молча сообщает «изменений
нет». Поэтому бот сам определяет версию каждой стороны (ключ верхнего уровня
`swagger:`) и сторону со Swagger 2.0 сначала преобразует в OpenAPI 3.0 утилитой
`oas2to3` (`tools/oas2to3`, kin-openapi `openapi2conv`, без загрузки внешних ссылок) в
той же песочнице без сети. Если в MR спецификация переходит со Swagger 2.0 на OpenAPI 3.x,
преобразуется только старая сторона. Если стороны объявляют разные версии 3.x (3.0 и
3.1), oasdiff запускается с `--auto-upgrade`.

- Номера строк в выводе oasdiff относятся к преобразованному файлу, поэтому для
  преобразованной новой стороны они не используются: тред несовместимости создаётся
  на файл (обычный тред «вне диффа»), в сводке строк нет.
- Нет `oas2to3` в образе → «⚠️ Проверка oasdiff недоступна: oas2to3 не установлен в
  sandbox-образе — спецификацию Swagger 2.0 нельзя сравнить…»; преобразование не
  удалось → «Проверка oasdiff не выполнена». «Несовместимых изменений не найдено» в
  этих случаях не пишется.

#### Внешние `$ref`

У oasdiff загрузка внешних `$ref` по умолчанию включена (риск SSRF на чужих
спецификациях), а `--allow-external-refs=false` запрещает и относительные ссылки на
соседние файлы. Поэтому бот сначала сам просматривает спецификацию и файлы, на которые
она ссылается:

| Что нашлось | Что делает бот |
|---|---|
| внешних `$ref` нет | `--allow-external-refs=false` |
| только относительные ссылки на файлы внутри репозитория (`./schemas/user.yaml`) | `--allow-external-refs=true`: файлы лежат рядом, сети в песочнице нет |
| ссылка по URL, абсолютный путь, выход за пределы репозитория (`../../..`), значение, которое бот не может надёжно разобрать | oasdiff не запускается, «⚠️ Проверка oasdiff не выполнена: …» |

### 2. Claude

В том же запуске ревью Claude ищет то, чего не видят инструменты: события,
миграции, конфиг, REST без спецификации, изменённые умолчания. Результаты
инструментов он получает как данные и не повторяет их. Каждый пункт Claude
блокирует мерж независимо от `review.block_min_severity`.

Исключение — файлы миграций БД, когда в MR есть миграции и включён
`review.migrations` ([migrations.md](migrations.md)): для них Claude пишет не пункты
совместимости, а замечания (поломка задеплоенного кода — critical с проверяемым
`deployed_usage`); пункт к файлу миграции бот всегда превращает в обычное
неблокирующее замечание.

### 3. Перепроверка

Новые пункты Claude (кроме уже открытых тредов) проходят **один** дополнительный
запуск Claude только на чтение кода (Read/Grep/Glob), задача которого — опровергнуть
каждый пункт: поле всё ещё принимается, эндпоинт внутренний, миграция — expand-фаза,
default сохраняет поведение.

- Подтверждённые публикуются, отклонённые видны в саммари в свёрнутом блоке
  «Отклонено при перепроверке».
- Это **тот же** запуск, что перепроверяет critical/major замечания ревью
  ([verify.md](verify.md)): если в ревью есть и замечания, и пункты совместимости,
  Claude проверяет их за один запуск (у пунктов совместимости свои правила и свои
  вердикты `confirmed`/`rejected`, как раньше). Если перепроверять нечего, кроме
  пунктов совместимости, запуск ровно тот же, что и раньше. Модель и таймаут —
  `review.verify.model` / `review.verify.timeout` (по умолчанию `claude.model` /
  `claude.timeout`); `review.verify.enabled: false` выключает только перепроверку
  замечаний, пункты совместимости перепроверяются всегда.
- Перепроверка учитывается в общем лимите и на `/usage` как вид «Перепроверка».
- Если общий лимит исчерпан или запуск не удался, пункты публикуются с пометкой
  «⚠️ Не перепроверено (достигнут общий лимит запусков Claude) — считается
  блокирующим, пока не доказано обратное.», а на `/problems` появляется проблема
  `verify_failed` ([problems.md](problems.md)).
- Результаты инструментов не перепроверяются.

### 4. Сводка изменений API

Тот же запуск `oasdiff changelog` даёт полный список изменений спецификации, не только
ломающих (одна команда на спецификацию; ломающие изменения и их идентификаторы те же,
что у `oasdiff breaking`). Тексты — на языке репозитория (`language`: `ru`, иначе
английский). Изменения только в описаниях (`description`) oasdiff не показывает.

Список сгруппирован по эндпоинтам (`METHOD path`), отдельно — новые и удалённые
эндпоинты:

| Значок | Уровень oasdiff | Что значит |
|---|---|---|
| ⛔ | ERR | ломающее изменение (оно же — блокирующий тред проверки совместимости) |
| ⚠️ | WARN | возможно ломающее, инструмент не уверен |
| ➕ | INFO | добавление (эндпоинт, необязательное поле, код ответа) |
| ℹ️ | INFO | прочее совместимое изменение (deprecation, теги, operationId…) |

Кто видит:

- **Claude** — в промпте ревью как недоверенные данные. Он проверяет, что код
  соответствует изменению спецификации (для нового эндпоинта есть обработчик, типы,
  обязательные поля, enum и коды ответов совпадают), и ищет потребителей каждого
  изменённого или удалённого эндпоинта в этом репозитории и в репозиториях контекста
  ([context.md](context.md)); широкий поиск он отдаёт сабагенту `code-search`
  (`claude.search_model`). Перепроверка пунктов Claude тоже получает этот список как
  контекст.
- **Люди** — в саммари MR сразу после раздела «🧩 Обратная совместимость», свёрнутым
  блоком на каждую спецификацию.

Размер ограничен: до 150 пунктов на спецификацию и 300 на MR (ломающие — первыми),
остальное — числом («…и ещё 12 изменений не показаны: ⛔ 0, ⚠️ 1, ℹ️ 11»).

Сводка строится **и при выключенной проверке совместимости** (`compat.enabled: false`
в репозитории или `review.compat_check: false` в конфиге сервиса): тогда запускается
только `oasdiff changelog` по OpenAPI/Swagger (с учётом `compat.openapi`), без buf и
graphql-inspector, ничего не публикуется тредами и мерж не
блокируется. Если сводку построить не удалось, в саммари будет строка «ℹ️ Сводка
изменений API для `…` не построена: …».

## Как выглядит в MR

Раздел саммари сразу после строки статуса мержа:

```markdown
### 🧩 Обратная совместимость

⛔ **Найдено 2 несовместимых изменения** — мерж заблокирован до исправления:

- **oasdiff** · `api/openapi.yaml:120` — removed the required property 'id' from the response
- **анализ Claude** · `db/migrations/0042.sql:3` — Колонка users.email удалена до contract-фазы
  - Было: колонка есть → Стало: колонка удалена
  - Безопасная альтернатива: перестаньте читать колонку в этом релизе, удалите в следующем

⚠️ Проверка buf недоступна: buf не установлен в sandbox-образе.
```

или «✅ Несовместимых изменений не найдено.»

Сразу за разделом — свёрнутая сводка изменений API (в GitLab видна только строка
`<summary>`):

```markdown
<details>
<summary>📘 Изменения API: api/openapi.yaml — 3 ломающих, 2 совместимых; эндпоинты: +1, −1</summary>

**Новые эндпоинты:**
- ➕ `GET /orders/{id}/history` · стр. 35

**Удалённые эндпоинты:**
- ⛔ `DELETE /orders/{id}` — API удалён без deprecation

**Изменённые эндпоинты:**

`POST /orders`
- ⛔ поле запроса `currency` стало обязательным · стр. 14
- ⛔ у свойства ответа `total` `type` изменён с `number` на `string` для статуса `200` · стр. 27
- ➕ добавлено новое необязательное поле запроса `comment` · стр. 18

</details>
```

Каждое несовместимое изменение — отдельный **блокирующий тред** (inline, если строка
в диффе, иначе обычный тред с файлом и строкой):

```markdown
**🧩 Breaking change** · Колонка users.email удалена до contract-фазы

⛔ **Блокирует мерж:** обратно несовместимое изменение. При rolling deploy старая и
новая версии работают одновременно, поэтому изменение должно быть совместимо в обе
стороны. Исправьте и закройте тред.

_Источник: анализ Claude (миграция БД)._

**Было:** …
**Стало:** …
**Безопасная альтернатива:** …

_Подтверждено перепроверкой: код предыдущей версии читает users.email в UserRepo.Get_
```

Повторно тот же пункт (тот же источник, файл и правило) не публикуется, пока тред
открыт. Треды учитываются в строке «⛔ Мерж заблокирован».

## Когда тред закрывается

| Источник | Закрывается, когда |
|---|---|
| инструмент | инструмент в этот раз **отработал полностью** и больше не находит проблему |
| Claude | Claude на следующем ревью сообщает, что проблема устранена |

Закрывает служебный токен; без него бот пишет «✅ Похоже, исправлено… _Тред можно
закрыть._» (см. [review.md](review.md#автозакрытие-исправленного)). Ответ на вопрос в
таком треде его никогда не закрывает.

## Ручное закрытие

Если человек закрыл тред несовместимого изменения сам (без ответа бота
«исправлено»), это осознанное решение: изменение принято. Бот больше не создаёт этот
тред, не блокирует мерж по нему и пишет в саммари:

```markdown
Тред закрыт вручную (изменение принято осознанно, мерж не блокирует):
- **анализ Claude** · `db/migrations/0042.sql` — Колонка users.email удалена до contract-фазы
```

Команда `@бот resolve` (закрыть все треды бота) действует так же: после неё эти
пункты считаются принятыми.

## Настройка

```yaml
# config.yaml
review:
  compat_check: true    # false — выключить во всех репозиториях (сводка API остаётся)
  compat_timeout: "3m"  # на один запуск инструмента
```

```yaml
# .reviewbot.yaml
compat:
  enabled: true                       # false — выключить для репозитория (сводка API остаётся)
  openapi: ["contracts/*.yml"]        # дополнительные пути
  proto: []
  graphql: []
```

Все проверки — инструменты **бота** из образа песочницы (exec-контейнер без сети и
токенов), а не модели: модель команд не запускает, код репозитория не исполняется.

## Ограничения

- Проверка не роняет ревью: если инструмент упал или отсутствует, в саммари будет
  «⚠️ Проверка X недоступна: …» или «⚠️ Проверка X не выполнена: …», а отсутствие
  инструмента не считается несовместимостью.
- Claude может ошибаться в обе стороны; перепроверка снижает число ложных
  срабатываний, но не убирает их. Для спорных случаев есть ручное закрытие.
- Контекст других репозиториев ([context.md](context.md)) помогает Claude найти
  реальных потребителей меняемого API.
- Swagger 2.0 сравнивается через преобразование в OpenAPI 3.0: редкие конструкции
  Swagger 2.0 (например, `collectionFormat`, `formData` со сложными схемами) после
  преобразования могут выглядеть иначе, чем их задумал автор.
