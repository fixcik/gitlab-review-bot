# Покрытие нового кода

Бот показывает, какая доля **добавленных и изменённых строк** MR покрыта тестами, и
передаёт Claude непокрытые изменённые строки, чтобы он отмечал важную логику без
тестов. Ни бот, ни Claude ничего не запускают: отчёт о покрытии берётся из артефакта
CI и разбирается ботом.

## Подключение

1. Пусть джоба тестов в CI сохраняет отчёт в артефакты:

   ```yaml
   # .gitlab-ci.yml — пример для Python
   tests:
     script:
       - pytest --cov=app --cov-report=xml:build/coverage.xml
     artifacts:
       paths: [build/coverage.xml]
       reports:
         coverage_report: {coverage_format: cobertura, path: build/coverage.xml}
   ```

   PHP: `phpunit --coverage-cobertura build/coverage.xml` или
   `--coverage-clover build/clover.xml`. Go: `go test -coverprofile=build/cover.out ./...`.

2. Укажите джобу и путь в `.reviewbot.yaml` (целевой ветки):

   ```yaml
   coverage:
     job: "tests"
     path: "build/coverage.xml"
     min: 80          # необязательно: предупреждение, если ниже (мерж не блокирует)
   ```

   Несколько джоб (unit + integration) — списком; строка считается покрытой, если её
   покрыл любой отчёт:

   ```yaml
   coverage:
     reports:
       - {job: "unit", path: "build/unit.xml"}
       - {job: "integration", path: "build/integration.xml"}
   ```

   Имя джобы совпадает и с её параллельными копиями (`tests 1/3`, `tests 2/3`) —
   их отчёты объединяются.

Форматы определяются сами: **Cobertura XML** (coverage.py, PHPUnit, gocover-cobertura),
**Clover XML** (PHPUnit, Jest/istanbul), **Go cover profile**, **LCOV**. Абсолютные пути раннера
(`/builds/group/project/src/x.php`) и пути от корня исходников сопоставляются с файлами
репозитория по самому длинному общему хвосту.

## Как выглядит

```markdown
<details>
<summary>🧪 Покрытие нового кода: 64% (45 из 70 строк) — ⚠️ ниже 80%</summary>

| Файл | Покрыто | Не покрыты строки |
|---|---|---|
| `app/orders.py` | 40% (2/5) | 3-6 |
| `app/billing.py` | 90% (36/40) | 51, 77-79 |

Нет в отчёте: `app/new_module.py` — тесты их не выполняли, файлы исключены из покрытия или путь не совпал.

Отчёт: tests · пайплайн #123 · cobertura
</details>
```

- Считаются только исполняемые строки из отчёта: комментарии, пустые строки и
  объявления не влияют на процент. Файлы из `ignore` не учитываются.
- Непокрытые строки, разделённые только неисполняемыми, объединяются в диапазон.
- Блок стоит после «🌿 Trunk-based».

## Когда появляется

| Состояние пайплайна последнего коммита | Блок |
|---|---|
| ещё выполняется или не создан | «⏳ жду завершения пайплайна»; бот перепроверяет каждые 2 минуты (до 3 часов) и обновляет только этот блок, без Claude |
| прошёл | процент и таблица |
| упал, отменён, пропущен | «⚠️ пайплайн упал — отчёта о покрытии нет» |
| нет пайплайна | «⚠️ у MR нет пайплайна» |
| джоба не найдена, файла нет в артефактах (или они истекли), формат не распознан | «⚠️» с причиной — так видно ошибку в конфиге |

## Для Claude

Если отчёт уже есть к моменту ревью или вопроса в треде, бот сам считает покрытие
изменённых строк и отдаёт Claude готовый результат (в клон ничего не кладётся,
команд у Claude нет):

- **без MCP** — в конце промпта (не в системном промпте: он одинаков для всех MR
  репозитория и кэшируется) итоговый процент и непокрытые изменённые строки
  по файлам, сначала наименее покрытые (не больше 20 файлов и 10 диапазонов на
  файл, остальное — «and N more»):

  ```
  CI coverage report: 64.3% of the changed executable lines are covered (45 of 70). Uncovered changed lines (new line numbers), least covered first:
  - app/orders.py: 2 of 5 covered; uncovered changed lines 3-6
  - app/billing.py: 36 of 40 covered; uncovered changed lines 51, 77-79
  ```

- **с MCP** ([mcp.md](mcp.md)) — в промпте только итог, а построчно Claude
  спрашивает инструмент `coverage` (с необязательным фильтром по пути).

Claude отмечает
непокрытую **важную** логику (ветвления, обработку ошибок, расчёты, изменения
состояния) как minor, на критичных путях (деньги, авторизация, потеря данных) — major.
Логирование, простые геттеры и связывание не отмечаются.

Если пайплайн ещё идёт, у Claude отчёта нет; блок в саммари обновится позже, но
повторного ревью ради покрытия бот не запускает (`@reviewbot review` после пайплайна
даст Claude отчёт).

## Ограничения и безопасность

- Нужен доступ бот-аккаунта к артефактам (Reporter достаточно). Артефакты дочерних
  (downstream) пайплайнов не ищутся — джоба должна быть в пайплайне MR.
- Отчёт не больше `review.coverage.max_report_mb` (50 МБ).
- GitLab часто отдаёт артефакт редиректом на объектное хранилище: токен бота на
  другой хост не пересылается.
- Отчёт разбирается как данные (XML без внешних сущностей), ничего не исполняется.

## Настройка сервиса

```yaml
review:
  coverage:
    enabled: true        # false — выключить во всех репозиториях
    max_report_mb: 50
```
