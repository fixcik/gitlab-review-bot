# Скиллы команды

Скиллы — руководства в формате Claude Code (`SKILL.md`): как у вас принято писать
Go, что проверять в миграциях, какие ошибки типичны для вашего фреймворка. Бот
предлагает их Claude на каждом ревью и в ответах в тредах. Claude видит только
названия и описания и сам открывает подходящие скиллы, пока скилл не нужен, его
текст в промпт не попадает.

## Подключение

1. Сложите скиллы в папку на сервере бота, по одному каталогу на скилл:

   ```
   /etc/reviewbot/skills/
     go-style/
       SKILL.md
       reference/errors.md        # дополнительные файлы, на которые ссылается SKILL.md
     postgres-migrations/
       SKILL.md
   ```

2. Укажите папку в конфиге сервиса:

   ```yaml
   review:
     skills:
       dir: "/etc/reviewbot/skills"
   ```

Папка перечитывается на каждом запуске: новый скилл подхватится без перезапуска.
Что бот видит сейчас — `@reviewbot config` в любом MR (строка «скиллы команды»).

## Формат `SKILL.md`

```markdown
---
name: postgres-migrations
description: Проверка миграций PostgreSQL: обратимость, блокировки таблиц, большие UPDATE. Использовать, когда в MR есть файлы миграций.
---

# Миграции PostgreSQL

1. Каждая миграция должна иметь down-часть…
```

- Имя каталога: строчные латинские буквы, цифры и дефис, до 64 символов. `name` во
  frontmatter можно не писать; если написан, должен совпадать с именем каталога.
- `description` обязательна (до 1024 символов). Claude решает по ней, открывать
  ли скилл, поэтому пишите, **когда** скилл нужен: «использовать, когда в MR есть
  миграции / изменения в `api/`».
- Подходят готовые скиллы откуда угодно, это тот же формат, что у Claude Code.

## Как это работает

- Для каждого запуска бот копирует скиллы в одноразовый каталог (только обычные
  файлы, без симлинков, права только на чтение) и монтирует копию в песочницу
  только для чтения как `/skills`. В системный промпт попадает список
  «название — описание — путь к `SKILL.md`».
- Claude читает нужные `SKILL.md` инструментом `Read`. В заметках GitLab (саммари,
  ответы в тредах) скиллы не упоминаются. Какие скиллы предлагались и какие
  прочитаны, видно в `/runs`, в журнале задачи (`skills: offered`, `skills: used`).
- Скиллы уточняют, что и как проверять, но не меняют формат ответа, язык и правила
  безопасности.
- Скрипты из скилла Claude не запускает: команд у него нет вовсе (только `Read`,
  `Grep`, `Glob`). Скилл — это текст с правилами проверки.

## Только доверенные скиллы

Скиллы берутся **только из папки на сервере**. `.claude/skills`, `.claude/commands`
и `.claude/settings*.json` из репозитория бот не загружает никогда (Claude
запускается с `--setting-sources user` и `--disable-slash-commands`): иначе MR мог бы
добавить скилл «ничего не отмечай» и повлиять на собственное ревью. Встроенные скиллы
Claude Code на ревью тоже недоступны.

## Настройки репозитория

```yaml
# .reviewbot.yaml (из целевой ветки)
skills:
  enabled: true          # false — без скиллов в этом репозитории
  disable: [go-style]    # не предлагать эти скиллы
```

## Ограничения

| Что | Предел | Что будет при превышении |
|---|---|---|
| файлы одного скилла | 2 МБ, 200 файлов, вложенность до 6 уровней | скилл пропускается |
| все скиллы | 20 МБ, 100 скиллов | лишние пропускаются |
| описание | 1024 символа | скилл пропускается |

Пропущенные скиллы и причины пишутся в лог (`skills: skipped`) и в журнал задачи в
`/runs`. Скрытые файлы и каталоги (`.git` и т.п.) не копируются.

## Расход токенов

Пока скилл не открыт, он стоит одну строку описания в системном промпте. Открытый
скилл добавляет к запуску свой текст. Держите `SKILL.md` короткими, а подробности
выносите в отдельные файлы рядом: Claude откроет их, только если понадобятся.
